# MuGLe

You can code music, but what if music could code? The primary goal of this is to make computer interaction pleasurable and the language semi-intuitive. The acronym stands for Musical Gesture Language, plus it rythms with "Bugle" and I like Muggles (Harry Potter ref.)

Additional goals include: 
- Non-stacking layers of complexity (more advanced functionality should not have overlap with basic functionality in the notes style, order, or speed)
- language that still enables musical theory to produce actual songs.
- It should not be turing complete nor be able to write fully autonomous code, as this competes with being enjoying and intuitive without an insane amount of work. 

I will start it as a purely command language to do simple math and input music on the computer to be composed later. It is optionally going to include additional syntax for functions calls and variables that include later music.
